# Composite review — NBT-Editor, 2026-09-17

Four independent passes over the fork's changes since the 2.0.3 divergence, merged: a
thermo-nuclear code quality review (structure and maintainability), a two-axis review splitting
Standards (repo conventions plus a Fowler smell baseline) from Spec (fidelity to the specs, ADRs
and roadmap), and a ponytail review (over-engineering and deletable volume). Each pass ran without
sight of the others. Nothing here is implemented yet.

**Range.** `v2.0.3...HEAD`, three-dot. `v2.0.3` is an upstream-only tag and is *not* an ancestor of
`main`; the true merge base is `5c59877` ("v2.0.2"). The range is exactly the fork's 13 commits,
`993d2a1` through `c8e08ee`.

**State at review.** Branch `main` at `c8e08ee`, tagged 3.0.0. 521 files changed. Java alone:
463 files, +15,037 / −14,650 — 104 added, 96 deleted, 261 modified. Total Java under `src/` went
**36,604 → 35,510 lines**, a net deletion achieved while migrating two Minecraft releases,
absorbing the 1.21.9 GUI rewrite, and adding 90 tests, a 354-line mixin verifier, and a headless
dev harness. `Reflection.` call sites went **316 → 1**. No file crosses 1000 lines at either end of
the range, and every one of the largest files shrank (`MVMisc` 795→0, `MainUtil` 550→0,
`MultiLineTextFieldWidget` 975→856, `FormattedTextFieldWidget` 902→717, `ClientChest` 849→695).

**Measurement note.** Upstream used CRLF, this fork uses LF. A plain `git diff` reports
+20,716 / −20,329 on Java, of which roughly 5,700 lines are pure line-ending churn. Every figure
above and every review below used `git diff --ignore-cr-at-eol -w`. Repeat that flag or the
numbers will not reproduce.

---

## The spine: the code outran its own record

Every pass arrived at the same fact from a different direction, so it belongs at the top.

The structural work in this range is good and the measurements back it: complexity was deleted
rather than relocated, the 26.2 migration landed, and the `multiversion/` package finally started
emptying. The thermo-nuclear pass approves it. The ponytail pass declined to flag five separate
things because CLAUDE.md or an ADR justified them, which is the correct outcome for a codebase
whose constraints are genuinely non-obvious.

What did not keep up is the *record* of that work. `ROADMAP.md` § Unresolved is false on all three
of its bullets. ADR-0003 and Roadmap 4.4 carry counts the code has since disproved. Roadmap 4.5
says nothing has been run in-game and the next section of the same file contradicts it. Two
commits claim cleanups — `e5965f1` "dismantle MixinLink", ADR-0003's "every such call lives in
`AccessWidenedApi`" — that the code only half performed, and `MixinLink` now carries an excellent
new docstring that contradicts two members the file still holds.

The same gap runs inbound. The September sync missed an upstream fix that upstream's own commit
message names in plain language. And the release commit bumped `gradle.properties` while the jar's
declared version stayed behind, because the `expand` that was supposed to carry it across has
never worked — upstream kept that literal in sync by hand and the fork walked into the trap.

Two of the three most user-visible defects found here are one-line fixes. Neither is a design
problem. Both are bookkeeping that no check was watching.

## Part 1 — Thermo-nuclear: structural quality

Verdict: **approve, with two blocking conditions.**

**1. `ConfigScreen.loadSettings` writes a half-loaded config to disk.** `ConfigScreen.java:221-293`
assigns 26 defaults, then performs 26 sequential reads inside one `try`, whose
`catch (NoSuchFileException | ClassCastException | NullPointerException)` calls `saveSettings()`.
A single missing or malformed JSON key throws mid-sequence, and the handler then *persists* a state
in which every field before the failure holds its loaded value and every field after holds its
default. A `settings.json` missing `jsonText` silently destroys the user's `shortcuts`, `aliases`,
`checkUpdates` and `creativeTabsPos`. Aliases and shortcuts are user-authored data, not toggles.

*Correction to the reviewer's framing, established on verification:* this is inherited verbatim
from upstream `v2.0.3` — identical catch clause, identical `saveSettings()` call. It is **not** a
regression this range introduced. The accurate charge is that the range rewrote this file heavily
(1,259 lines changed) and left a live data-loss path untouched, while giving the client chest the
ADR-0002 hardening the config file never received.

**2. `misc/DevScreenSweep` ships in the production jar.** 153 lines of screen-clicking test robot
driven by three system properties, living in `src/main/java/` and installed unconditionally from
`NBTEditorClient.onInitializeClient`. It belongs in a `dev` source set.

**3. `ConfigScreen` is the god object the 2026-09-14 audit never named.** 625 lines; each of 26
settings appears in five hand-maintained places, roughly 156 correspondences, with seven
undocumented legacy wire-name mappings and a double negation. A `Setting<T>` table deletes about
300 lines and is the durable fix for finding 1.

**4. `Drawing.renderItem` ignores its `zOffset` and `setScreenZOffset` parameters entirely** while
three call sites still pass `200.0F, true` / `100.0F, false`. The API describes behaviour it does
not have, inside a class that is 12 pass-throughs wrapped around 5 real methods.

**5. `multiversion/MVTextEvents` (199 lines, new) violates ADR-0001's "do not add new `MV*`
wrappers".** It is a good sealed-hierarchy descriptor model for fancy-text click and hover events,
placed in the one package the fork has an accepted decision to empty.

Runners-up: `ConcatContainerIO` repeats one array-slicing walk three times — the exact tri-method
invariant ROADMAP 3.3 documented in prose; `MixinLink`'s new docstring contradicts two members it
still holds, including an unbounded unsynchronised `HashMap`; `ClientChest.getDataVersion` returns
`Optional<Optional<Integer>>`; `ConfigList` is 68% one 297-line private inner class; `ROADMAP.md`
describes a `PartitionedLockImpl` defect this range already fixed.

Standouts worth repeating elsewhere: the `MainUtil` partition (measurement-first — 70% of 384
references turned out to be one field — and it surfaced two real bugs including an in-render
infinite loop), `PageTasks`, and `util/TextSearch`.

## Part 2 — Standards: conventions and smells

Documented-standard breaches:

1. **`multiversion/Attempt.java` contradicts CLAUDE.md's placement rule** — "a deep one whose
   package is the only thing version-flavoured about it belongs in `util/` instead." `Attempt` is a
   `DataResult` wrapper with nothing version-flavoured, and the fork moved it *up* into
   `multiversion/` during a dismantle. Same for `multiversion/nbt/manager/`, moved deeper in.
   Credit where due: the MV class count went 28 → 21, exactly ADR-0001's stated target.
2. **`misc/MixinLink.java` survives at 156 lines** despite `e5965f1` claiming to dismantle it.
   `hiddenExceptionHandlers`, `specialNumbers`, `ITEM_BEING_RENDERED` and `SET_CHANGES` are still
   four bare thread-keyed globals, which is AUDIT T2's open complaint verbatim. The pattern also
   *spread*: fork-new `screens/containers/ClientScreenHandlerSlot.UNLOCKED_THREADS` is a fifth
   hand-rolled copy of the `add(currentThread)` / `try` / `finally remove` idiom.
3. **`util/Futures.java` is pure JVM logic with no test**, against ADR-0004. Everything else new
   and pure in the range does have one.

Baseline smells, all judgement calls:

4. **`ItemBlockContainerIO` and `ItemEntityContainerIO` are the same record twice** — same shape,
   same four factories, same `withTextures`; only the local type and registry-key lookup differ.
   One generic `ItemPairContainerIO<L extends LocalNBT>` erases about 38 lines.
5. **`ContainerIOs` duplication with a live cost** — see Verified findings, items 3 and 4.
6. **`multiversion/nbt/manager/` is speculative generality** — with `nbt/nbt/NBT*Manager` deleted,
   `NBTManager<T>` and `DeserializableNBTManager` have one implementation each, and the
   `Component*` prefix distinguishes them from something that no longer exists.
7. **`containers/ContainerIOs` and `util/BlockStateProperties` import `server/ServerMVMisc`**,
   which ADR-0005 records as unreachable in a client-only jar.
8. **`util/SlotUtil` is primitive-obsessed** — three `int` slot spaces, a six-way conversion
   matrix, `is`/`extract`/`create` triplicated across all three. Inherited, not this fork's design;
   recorded for completeness only.

Praise, for calibration: `PageTasks` collapsed AUDIT T1's eight near-identical async methods into
two, is Minecraft-free, and arrived with 244 lines of test. It is the best work in the diff.

## Part 3 — Spec: fidelity to what was asked

The axis opens clean on the claims most likely to be wrong. All five of `993d2a1`'s stated defects
are genuinely in the diff (`updateOk()` wired and called from the constructor, `StyleOption.get`,
the `";"` terminator, the `IndexOutOfBoundsException` catch and FONT-null guard, `setDaemon(true)`).
ADR-0001's "21 remain" holds at 21. `c8e08ee`'s README section exists. All ~60 sync-spec items
carry a `Result:` line.

Missing or partial:

1. **ADR-0003 is half implemented.** "Every such call lives in `util/AccessWidenedApi`, one method
   per widener line" — 5 methods against roughly 35 widener entries. Widened members are read
   directly in `StyleUtil.java:55,84` and `:38`, `ContainerScreenInput.java:49`,
   `FancyText.java:157`, `CursorManager.java:110`. Three of the five members the ADR's own Context
   cites as its motivation sit outside the class it created.
2. **Seven widener lines have zero consumers**, against ADR-0003's "deleting a widener line makes
   exactly one file stop compiling": `TagTypes TYPES`, `GlStateManager SCISSOR` / `$ScissorState` /
   `$BooleanState enabled`, `GameRenderer renderBuffers`, `MenuScreens register` /
   `$ScreenConstructor`. The scissor group is residue of `b8bd859`, whose own spec entry calls
   those entries moot.
3. **The mandated verification was never recorded.** The sync spec's Mechanics section requires
   `scripts/dev-client.sh --screens` after any group touching a screen, a container IO, or the
   registry path. `37ebc35` touches `ContainerIOs`, `ContainerComponentContainerIO`, `NbtFormatter`
   and screens. Every `Result:` proves itself by `javap` or a source probe; none records a sweep or
   join run. `25dd620` says `DevScreenSweep` "is what caught it" and then logs no passing sweep
   after the fix.
4. **`util/Futures` and `util/DataFixes` arrived untested**, against ADR-0004. (Reached
   independently by the Standards axis — the one place the two axes converge.)
5. **The 3.0.0 jar declares itself 2.0.4.999.** See Verified findings, item 1.
6. **No `.scratch/<slug>/issues/` directory exists** despite `docs/agents/issue-tracker.md`
   mandating one file per ticket; the sync spec header is still `Status: needs-triage` with every
   item ticked.

Scope creep:

7. **ADR-0005 was never extended to cover `--screens`.** The sweep, `misc/DevScreenSweep` and the
   `NBTE_SCREENS_NBT` / `_FROM` knobs arrived in `25dd620` against an ADR that names three
   verification layers and describes `dev-client.sh` as boot plus `--join`. Minor, and it caught
   the `class_634` defect.

Implemented but wrong:

8. **`ROADMAP.md` § Unresolved is false on all three bullets.** `depends.minecraft` is `">=26.2-"`,
   not `">=1.17-"`; nbt-autocomplete is `1.3.15-fabric-26.2`, not "pinned to
   `1.3.12-fabric-1.21.5`"; ADR-0001 settled `multiversion/`. Three closed questions read as open.
9. **Roadmap 4.5's "nothing in phases 1 through 4 has been run in-game" is contradicted by the next
   section of the same file.** Phase 1 and Phase 3's "not exercised in-game" are equally stale. Two
   of 4.5's three flagged runtime risks are resolved — `MVTooltip`'s GL scissor code is deleted and
   `ScreenMixin`'s `require = 0` is covered — and the roadmap does not say so.
10. **Stale counts.** ADR-0003 says "Reflection survives at two call sites in `server/`"; one does,
    at `NBTEditorServer.java:150`. Roadmap 4.4 says "Five intermediary names survive"; one does.
11. **Roadmap 2.1's per-keystroke world-entity scan is correctly unticked and still live** at
    `fancytext/FancyTextStyleOptionNode.java:57`, shipped under a 3.0.0 tag.

## Part 4 — Ponytail: what to cut

`net: -399 lines possible.` Highest-value first:

- `util/lock/PartitionedLockImpl.java:10-14,67-82` — `stdlib:` hand-rolled striping: a
  `ConcurrentHashMap<Integer, Lock>` behind a global lock, to vend a `ReentrantLock` per partition.
  Guava `Striped.lock(64)`; `stop()` and the `isLocked` counter stay.
- `misc/DevScreenSweep.java:1-153` — `delete:` from `src/main`. See Part 1, blocker 2.
- `util/Drawing.java:61-119` — `yagni:` twelve one-line forwards to `GuiGraphicsExtractor` that
  exist only to preserve the mod's own method names. The file's own javadoc at L26 already says
  audit item A1 wants this.
- `util/Drawing.java:96` — `delete:` `renderItem`'s two unread parameters.
- `misc/MixinLink.java:95-106` — `yagni:` `renderChatLimitWarning` is screen drawing, which this
  file's own new javadoc at L44-47 says belongs in `screens.ItemTooltips` and
  `screens.containers.ContainerScreenInput`. Move it where the docstring already points.
- `util/ModResources.java:137-154` — `shrink:` eighteen lines wrapping and unwrapping
  `UncheckedIOException` around an `Optional.map` whose lambda throws. `getResource(id)` already
  returns `Optional<Resource>`; branch on it and call `open()` outside the map. Four lines, and
  both callers `orElseThrow()` regardless.
- `clientchest/PageTasks.java:38-42,76-78` — `yagni:` an `Access` enum plus `lockFor` to choose
  between exactly two locks. Take the `PartitionedLock` as the parameter.
- `build.gradle:48-58` + `scripts/dev-client.sh:17-18,36-43,108` — `yagni:` four `-P` properties
  and two env vars threaded gradle → JVM property → field, carrying a resume index and a
  `;;`-separated SNBT list for a tool with one user.
- `scripts/dev-client.sh:12,32` — `yagni:` `--join` parses `host:port` for "a server already

- Dead API with test-only callers: `util/lock/PartitionedLock.java:16` `isAllLocked`,
  `util/TooltipPlacement.java:60-63` `isUnchanged`.

  `read`, its only user, discards the return value.
- `util/ItemSizeText.java:32-43` — `shrink:` three getters on a nested enum read only at L77-78 of

- `PartitionedReadWriteLockTest.java:46-77,196-232` — `delete:` two tests asserting the

## Verified findings

Everything in this section was confirmed directly against the tree, not taken from a reviewer's
report. Commands are given so each can be re-checked.

1. **The 3.0.0 jar declares version 2.0.4.999.** `gradle.properties` has `mod_version = 3.0.0`.
   `build.gradle:88-93` runs `expand "version"` over `fabric.mod.json`. But `fabric.mod.json:4` is
   the literal `"version": "2.0.4.999"` with no `${version}` placeholder, so the expand substitutes
   nothing and silently succeeds. Upstream carried the same dead `expand` at `v2.0.3` with the
   literal `"2.0.3"`, kept in sync by hand, so the bug never surfaced there. No commit in this
   range touches the line, confirming `c8e08ee` bumped `gradle.properties` only.
   Fix: `"version": "${version}"`. This also retires the hand-sync permanently.
   `grep -n version gradle.properties src/main/resources/fabric.mod.json`

2. **`ConfigScreen.loadSettings` persists a partial config**, and the flaw predates the fork.
   `sed -n '221,300p' src/main/java/.../screens/ConfigScreen.java` and
   `git show v2.0.3:src/main/java/.../screens/ConfigScreen.java` — the catch clause is identical.

3. **The hopper minecart is registered with the wrong entity type, and upstream already fixed it.**
   `containers/ContainerIOs.java:115-116` passes `EntityTypes.FURNACE_MINECART`; line 175 registers
   that under `Items.HOPPER_MINECART`. Upstream `us/dev` has `EntityType.HOPPER_MINECART`, fixed
   2026-08-20 in `377e0c2`, whose message ends "fixed `/open` giving the wrong entity id to
   hopper_minecart items". `us/dev` is not an ancestor of `main` and `37ebc35` did not pick it up;
   `origin/dev` and `fork-thorioum/dev` both still carry the stale value. One identifier.
   `git show us/dev:src/main/java/.../containers/ContainerIOs.java | grep -A1 HOPPER_MINECART_IO`

4. **`HORSE_IO` and `BASIC_HORSE_IO` are byte-identical** at `ContainerIOs.java:100-103`, both
   `EquipmentContainerIO.forNbtCompoundEquipment(false)`. Upstream distinguished them with a
   `Version.newSwitch()`, so this is expected fallout of the ADR-0001 version collapse — the names
   simply outlived the distinction. Low stakes; collapse or rename.

5. **`Drawing.renderItem` ignores two parameters.** `Drawing.java:96`: the body is two `context`
   calls; neither `zOffset` nor `setScreenZOffset` is read. Call sites at
   `LocalItemStack.java:114`, `LocalItemParts.java:173`, `CreativeTabWidget.java:85`.

6. **Guava is on the classpath**, so the `Striped` swap is viable — already imported for `Cache` in
   `LargeClientChestPageCache`, `ThreadExecutorMixin` and `MixinLink` itself.

7. **`ROADMAP.md` § Unresolved bullet 1 is false.** `fabric.mod.json` `depends.minecraft` is
   `">=26.2-"`, not `">=1.17-"`.

8. **Headline metrics reproduce exactly.** Java LOC 36,604 → 35,510; `Reflection.` call sites → 1.

## Method and limits

Four reviewers ran in parallel on the same range, each given CLAUDE.md and ADRs 0001-0005 as
binding context so that deliberate constraints — no refMap, intermediary names in
`multiversion/Reflection.java`, JVM-only tests, single game version — would not return as findings.
The two-axis pass was kept deliberately split; its Standards and Spec findings are reported side by
side above and were never merged or reranked, because a change can pass one axis and fail the other.

**Coverage.** 463 changed Java files is past what any single pass reads line by line; all four
prioritised judgement over coverage and said so. The Standards axis read `containers/`,
`clientchest/PageTasks`, `util/`, `multiversion/`, `MixinLink` and `screens/containers/`, and did
**not** read most of `screens/`, `tagreferences/`, `tsp/headdb/`, mixin bodies, or tests. Absence of
a finding in an area is not evidence of its health.

**Attribution.** 24 of the 104 "added" Java files already existed at `v2.0.3` — `SlotUtil`,
`StyleUtil`, `fancytext/`, `ServerMainUtil`, `nbtfolder/` — and are upstream code re-adopted by
`993d2a1`, not fork design. Findings against them are recorded but should not be read as criticism
of this range's authorship.

**Two findings not to apply as written.**

- *`MixinLink.MAIN_THREAD` → `Minecraft.isSameThread()`.* The ponytail pass proposed this as a
  `native:` cut. `MixinLink.java:136` carries a comment it did not engage: "MinecraftClient#thread
  is set after the ClientModInitializers are run." The sole caller is
  `DynamicRegistryManagerHolder.getManager():98`, a registry path reachable during init, and
  `MinecraftClientMixin` sets `MAIN_THREAD` immediately after `ReentrantBlockableEventLoop.<init>`
  — earlier than vanilla assigns `gameThread`. If that ordering still holds in 26.2 the hand-roll
  is load-bearing and the swap would silently disable the guard during early init. Verify the
  ordering before touching it.
- *`Drawing.renderItem`'s parameters.* Deleting them is correct, but `200.0F` and `100.0F` are
  z-layering values the render-state extraction stopped honouring while leaving callers passing
  them. Check whether item z-ordering regressed in the GUI rewrite before assuming the parameters
  were always inert.

**Reproducing.** All four reports were written to `/tmp/nbteditor-review/` — `thermo/00_summary.md`
plus six per-subsystem detail files, `matt-standards.md`, `matt-spec.md`, `ponytail.md`. That
directory is ephemeral; this document is the durable record. No repository file was modified by any
reviewer.
